Claude Code plugin · flow v0.5.0

Route the work before you do it.

Most agent workflows start typing immediately. flow reads the task first, announces one of four routes in three lines, and then runs that route end to end — plan in phases, loop to done, look at the running app, hand off. It was mined from ~40 real sessions, not invented.

The switchboard

Four routes, one spine.

Two things ride alongside any route rather than inside it. Design — when more than one defensible visual answer exists, /flow:design runs first and returns three variants at both breakpoints. Research — any load-bearing external fact goes to a background researcher agent that writes a cited file and never blocks the turn.

A brainstorm about a screen evaluates that same design axis. /flow:explore runs the design pass on the direction it is about to recommend, before it publishes, and the variants land as a section of the options artifact rather than a page of their own. One link carries the ideas, the recommendation and the mockups — an idea about a screen is not readable until someone has seen the screen.

The engine

The plan is the state. The loop is stateless.

Route 2 is the one you'll live in. /flow:plan writes a phased checkbox plan and the prompt that executes it, from a single template, so the two can never drift. /flow:loop fills that template in and starts the runner — you never paste anything.

Why it's good

Four rules that came from receipts.

Each of these was expensive to learn. They are enforced by the plugin — by hooks and generated prompts — rather than by remembering them.

Rule 01 · measured

A phase is how long a session lives.

Across six sessions costing ~$1,116, 81% of spend was cache reads — paying again and again to re-read a transcript that had already served its purpose. Below ~260K of context an iteration cost $3–8. Above it, $17–124 for the same kind of work.

So phases are sized to five to seven tasks, and the session ends when one completes. Two things follow: an effort's cost is knowable before it starts, and the handoff stops being paperwork — it is the only thing that crosses the boundary.

Schematic of measured iterations. Re-derive it yourself with python scripts/measure-sessions.py.

Rule 02

Agents start fresh, never forked.

A forked reviewer inherits the reasoning that wrote the code — and agrees with it, which is the one thing a second reader must not do. Every agent here derives what changed from the git diff, the plan and the handoff: durable state that outlives the session.

Rule 03

Green tests don't perform.

In the mined corpus, every single front-end defect caught had already passed a green test run. So no UI change is called done on tests alone. /flow:eyes is required, and it produces durable desktop and mobile screenshots.

Rule 04

A wrong route costs one character.

Routing is announced in three lines with a one-token veto, not negotiated through a questionnaire. Route 3 is the only one that stops for confirmation first, because chartering a map is expensive.

How to use it

Two commands to remember.

Seven more sit underneath for when you want to drive one stage by hand. Small work routes to 0 and none of this applies — that is the point of a front door.

1

Add the dependency marketplace

The foggy route is answered by Matt Pocock's skills. A declared dependency that can't resolve leaves flow disabled, so add it first.

$ claude plugin marketplace add mattpocock/skills
2

Install flow

Installing pulls in mattpocock-skills automatically, and enabling flow enables it too.

$ claude plugin marketplace add KhaiStimpson/myworkflow $ claude plugin install flow@myworkflow
3

Hand it a task

Then start the loop that walks the plan to done. That's the whole daily surface.

$ /flow <the task> # routes it, runs it $ /flow:loop # walks the plan to done
The nine commands
/flowMacro. Front door — routes the task, then runs the route end to end.
/flow:loopMacro. Fills the loop prompt in from the plan and starts the runner.
/flow:startInvestigates, announces a route in three lines, one-token veto.
/flow:exploreBrainstorm with zero file changes → options with a recommendation, plus design variants on the same page when the idea is visual.
/flow:designThree variants, desktop + mobile → a decisions record that outranks the mockup.
/flow:planPhased checkbox plan plus the loop prompt that executes it. Implements nothing.
/flow:workOne slice, one branch, verify, screenshot, land on the integration branch.
/flow:eyesRun it and look at it, both breakpoints.
/flow:wrapHandoff file, or integration PR + tracker comments + README with screenshots.
The hooks — rules that hold whichever model is driving
HookWhenWhat it does
Session statestart / resumeInjects the live effort, phase, next unchecked task, branch, and where context sits against its budget. Resuming costs no keystrokes.
Phase boundaryend of turnDetects that the last task in a phase is ticked and says to commit, update the handoff, and continue on fresh context.
Context backstopend of turnFires at 250K — the measured knee — for the runaway task a phase boundary can't catch. One measured iteration burned 257 turns and $124 alone.
Image read guardbefore ReadBlocks a large screenshot read and hands back the path and size. One session spent 96% of everything it observed on 63 image reads.
Handoff spinesession end · pre-compactWrites branch, SHA, phase, chain position, next task and dirty files into the handoff, between markers. It never touches the prose.

Each hook exits silently when it doesn't apply — a repo with no live effort pays nothing. The scripts are POSIX sh; on Windows they need Git Bash, which is how Claude Code runs hooks there. scripts/run-gated.sh isn't a hook but belongs beside them: wrap your build and test commands in it and a green run costs one line instead of a thousand, with the full log on disk and failures shown in full.

flow encodes what one developer actually does, not what a methodology says — the plan-plus-loop-prompt pairing, the integration-branch topology, three variants at both breakpoints, and "stop and ask rather than guess" all come from repeated words in the corpus. Where the evidence was contested, the system asks once and records the answer rather than picking for you.
