# The loop prompt

The engine of route 2. Generated by `/flow:plan` alongside the plan file so the two cannot drift.
Paste after `/loop` (unattended, repeats) or `/goal` (drives to completion, attended).

## The anatomy — every clause earns its place

```
Open docs/<effort>-plan.md. Find the FIRST unchecked task in the checklist and implement
only that one task, following its phase description and the Ground rules section exactly.
Then run <build command> and <test command>. Tick that item [x] in the checklist. Commit
with a message naming the phase and task. Implement exactly one item per iteration. If the
task is ambiguous, blocked, or needs a decision I should make, stop and ask instead of
guessing. Do not skip ahead to a later task. If all items are checked, stop the loop.
```

| Clause | Why it is there |
|---|---|
| `FIRST unchecked task` | Makes the plan file the state. A crashed session costs nothing. |
| `only that one task` | The diff stays reviewable without anyone measuring it. |
| `Ground rules section` | Keeps the prompt short and the binding constraints in one editable place. |
| `run <build> and <test>` | The per-repo gate, named explicitly rather than assumed. |
| `Tick that item` | The tick **is** the progress record. Without it the loop repeats work. |
| `Commit naming phase and task` | The history reads as the plan, so a walkthrough is free. |
| `stop and ask instead of guessing` | The clause that makes unattended running safe. |
| `Do not skip ahead` | Dependency order is real; a later task built on an unbuilt earlier one is rework. |
| `If all items are checked, stop` | The loop terminates itself instead of burning turns. |

## Variants worth keeping

**Add for UI-touching efforts:**

```
If the task changes anything visible, capture desktop (1280x800) and mobile (390x844)
screenshots into docs/screenshots/<slug>/ and commit them with the change.
```

**Add when the effort has a tracker:**

```
After merging, comment on the GitHub issue that it landed, including the merge SHA.
Do NOT close issues.
```

**Add when the loop is running unattended overnight:**

```
Before the start of the next iteration, update HANDOFF-<effort>.md. If you stop for a
question, write the question into the handoff file before stopping.
```

## Two failure modes seen in practice

- **Delay between iterations** — say `Do not delay between loops` if the runner idles.
- **A plan gone stale against the tree** — when the app changed underneath the plan, re-run
  `/flow:plan` against the current repo before looping again rather than letting the loop
  reconcile it task by task.
